# Implementation Plan: AI Offer Analysis Plugin (`ai-offer-analysis`, port 3011)

## TL;DR
9 task groups, 58 steps, 18 Jest tests (10 domain + 8 route), 1 BAML test block, and a host `./mvnw test` regression run.
Order: scaffold (1) → BAML contract (2) and domain logic (3) in parallel → analyze route (4) and UI pages (5) → 013 seed (6, needs only 1) → docs (7) → test review (8) → live LiteLLM traffic run (9).
The UI group carries Visual References for all 7 screens and 2 components; `visual-coverage.md` shows 100% coverage.
Group 9 needs Docker, a real `OPENAI_API_KEY` and a browser. If the environment is missing during execution, it moves to the verification phase.

## Key Decisions
- **`generators.baml` goes in Group 1.** `npm install` runs the `postinstall` `baml-cli generate`, which needs a `baml_src/` directory. The scaffold group creates `generators.baml`; Group 2 adds `clients.baml` and `main.baml`.
- **The domain does not depend on BAML.** Per the spec, `src/domain.ts` never imports `baml_client`, so Group 3 depends only on the scaffold and can run alongside Group 2.
- **The UI depends on the domain, not the route.** The tab is coded against the spec's `/api/analyze` contract, so Group 5 can run alongside Group 4. Group 8 runs the final `npm run build` over the whole project.
- **Test Review adds no tests beyond the spec caps.** The spec sets success at ≤18 Jest tests (domain ≤10, route ≤8). Group 8 checks coverage against the spec's numbered test list and fills a gap only inside those caps, not with the template's "up to 10 additional" tests.
- **The live run comes after Test Review.** Group 9 depends on the environment. Putting it last means a missing environment never blocks the code-producing groups or Test Review. It is the only group allowed to move to the verification phase.
- **Host regression skips the npm build.** It runs `./mvnw test -Dskip.npm -Dskip.installnodenpm -Dskip.jooq.generation=true`. The seed changes no schema and the jOOQ sources already exist in `target/generated-sources/jooq`. TestContainers still needs Docker. No Liquibase context filter is set, so the dev-context 013 changesets load in host tests too, which is what this run checks.

## Open Questions / Risks
- **LiteLLM attribution recording is unknown until Group 9.** BAML 0.220 puts `metadata.tags` and `user` into the request body, but it is not yet known whether LiteLLM OSS stores them as `request_tags`/`end_user`. If it does not, Group 9 applies the `x-litellm-tags` header fallback to `clients.baml` and reruns the steps.
- **Shared files across groups.**
  - `plugins/ai-offer-analysis/README.md` is touched by Groups 7 and 9.
  - `baml_src/` is touched by Groups 1, 2 and 9.
  - Dependencies already put each pair in order, and both groups list the file.
- **The seed JSONB can drift from `manifest.json`.** Nothing enforces equality. Group 6 copies the manifest content verbatim and checks it with a JSON comparison.
- **UI pages have no Jest tests (out of scope per the spec).** The visibility gate, the single auto-run attempt and the mockup fidelity are checked only through the type-check, the Group 9 live run and the later E2E/visual verification.
- **LLM nondeterminism.** A demo product's price verdict may vary between runs. Acceptance needs only the strongly cued flag for each demo product.
