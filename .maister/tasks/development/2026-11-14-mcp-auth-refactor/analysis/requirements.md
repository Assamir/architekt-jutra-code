# Requirements: MCP auth refactor (validate-then-exchange)

## TL;DR
Replace MCP token passthrough with RFC 7662 introspection + `aud` check at the MCP server and RFC 8693 delegation exchange at the custom host AS; enforce `iss`/`aud` at host `/api`; fixed issuer; ports move to host 8180 / MCP 8181 / MCP mgmt 9181. MCP tools behave exactly as before for users; viewer gets read-only access. Docs and standards updated to match code.

## Key Decisions
- Architecture = research package P1 (ADR-001..009), refined by Phase 1/2 clarifications (fixed issuer, ports, resource hidden input, typed JSON authorize errors, C-1 slash-equal origin URIs, C-2 only T0 at consent, I-1..I-9).
- Reuse existing AS filters/repository/user-details service; delete passthrough classes.

## Open Questions / Risks
- Real client `resource` behaviour handled by C-1 normalisation; still worth a manual check with Claude Code / MCP Inspector after implementation.

Cel: wyeliminować podatności wynikające z bezpośredniego przesyłania wrażliwych danych uwierzytelniających pomiędzy warstwą MCP a usługami backendowymi." ## Q&A (Phase 5)
1. **User journey** — confirmed: user configures MCP client (Claude Code / MCP Inspector) at `http://localhost:8181`; login + consent in SPA at `http://localhost:8180`; tools `aj_list_products`, `aj_add_product`, `aj_list_categories` work as before. Personas: viewer (read-only), editor, admin. Viewer is offered/granted only `mcp:read` at consent; `aj_add_product` by a viewer ends with a tool error (insufficient scope).
2. **Existing code reuse** — confirmed: extend `OAuth2TokenFilter` (exchange grant branch), `DatabaseRegisteredClientRepository`, `CustomUserDetailsService` (current permissions at exchange), `OAuth2IntegrationTests` pattern; MCP keeps `McpAuthenticationEntryPoint` and `WellKnownController`; delete `McpJwtFilter`, `AccessTokenHolder`, `JwtForwardingInterceptor` (and their passthrough tests).
3. **Visual assets** — none. Only UI touches: hidden `resource` input on `OAuth2AuthorizePage.tsx`, consent page offers only grantable scopes, `AuthContext.loadStoredAuth` drops stored tokens without `aud`.

## Functional requirements summary
- **Host AS**: fixed issuer `app.oauth2.issuer`; `OAuth2Properties` (`app.oauth2.*`); `resource` (RFC 8707) parsed at authorize and token, origin-only URIs equal with/without trailing slash, canonical no-slash `aud`; missing → MCP URI + WARN, unknown → `invalid_target`; per-grant resource policy (authorization_code/refresh → MCP resource only; host-API audience only via token-exchange by `aj-mcp-server`); `ScopePolicy` (hierarchy `mcp:edit`⊃`mcp:read`, ∩ user permissions, ∩ client scopes; default to client's registered scopes when omitted); RFC 8693 token-exchange grant (subject T1 must be active, issued for the MCP resource; T2 `aud`=`${issuer}/api`, `act.sub`=MCP client id, `client_id`, current permissions, TTL ≤ min(300 s, T1 exp), response with `issued_token_type`, `expires_in`); RFC 7662 `/oauth2/introspect` (caller auth required, `active:false` for unusable tokens or tokens not bound to the caller's resource, space-delimited `scope`); `ClientAuthenticator` (Basic with URL-decoding + post, BCrypt; unknown client → `invalid_client`); `McpClientProvisioner` (idempotent upsert of `aj-mcp-server` from env reusing row id, sets client name; blank secret → delete stale row with WARN); refresh tokens bound to client + resource, validated before removal; metadata advertises `introspection_endpoint` and token-exchange grant; typed JSON errors (shared writer, `INVALID_TARGET`), status mapping fixed; no secret/token logging; Jackson 3 in touched code.
- **Host security**: every JWT carries `iss` + `aud`; T0 `aud`=`${issuer}/api`; `/api` accepts only `iss`=issuer and `aud`∋`${issuer}/api` (contains-match), leaving the context empty otherwise; remove `permissions→scopes` fallback; `/oauth2/authorize` accepts only session tokens (no `client_id`/`act`) as principal; `SecurityConfiguration` keeps `PERMISSION_mcp:*` matchers (T2 keeps `mcp:*`).
- **MCP server**: `spring-boot-starter-security-oauth2-resource-server`; explicit `SpringOpaqueTokenIntrospector` wrapped by `AudienceValidatingIntrospector` (`aud`∋`aj.mcp.base-url`, slash-equal); 401 with `WWW-Authenticate` (`error="invalid_token"`, `resource_metadata`); no `mcp:*` scope → 403 `insufficient_scope`; outage → 5xx, never `invalid_token`; `contextExtractor` stores validated `Authentication` in `McpTransportContext`; per-tool scope check (`ToolSecurity`); hand-written `TokenExchangeClient` (own RestClient, form POST, Basic auth URL-encoded, validates `issued_token_type`); T2 passed explicitly to `AjApiClient` per call; no caches; backend 401 → `apiError`, no retry; fail fast without `AJ_OAUTH_CLIENT_SECRET`; delete passthrough classes; no token logging, security DEBUG removed.
- **Ports & config**: host `server.port=8180`; MCP 8181, management 9181; defaults updated in MCP `application.yml`, Vite proxy, plugin `HOST_BASE_URL`/server-sdk defaults, `start-dev.sh`/`.ps1` (export `APP_OAUTH2_ISSUER`, `AJ_*` URLs, `AJ_OAUTH_CLIENT_ID/SECRET`, `APP_JWT_SECRET`), CORS origins env-overridable with local default, frontend test fixtures (14 lines); not `plugins/*/dist/`, `.playwright-mcp`, course dirs.
- **Docs**: CLAUDE.md, `.maister/docs/standards/mcp-server/conventions.md`, `backend/security.md`, `backend/plugin-auth.md`, `plugins/plugin-development.md` (port table), `project/architecture.md`, `project/tech-stack.md`, `INDEX.md`, plugin READMEs/CLAUDE.md port mentions.
- **Tests**: Phase 3 red tests must pass; HTTP-level security tests (T1 at `/api` → 401, T0 without/with wrong `aud`/`iss` → 401, exchange by non-MCP confidential DCR client → rejected, introspection auth, viewer cannot get `mcp:edit`, T2 at consent → rejected, refresh by other client → rejected, trailing-slash resource accepted); MCP passthrough-pinning tests rewritten/deleted; test config in `src/test/resources/config/`.
